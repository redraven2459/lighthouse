# Guidelines

Contributions are and will always be greatly appreciated provided they are in the spirit of Lighthouse's vision.

The following subsections are all about developing a contribution to Lighthouse. If you just want to suggest an improvement or report a bug: submit an issue on [Lighthouse's GitHub](https://github.com/redraven2459/lighthouse).

## Get familiar
Whilst not mandatory it is highly recommended to read the [Project Overview](project_overview.md) and to use the [Recommended Development Environment Setup](recommended_development_environment_setup.md).

## Develop a feature or bug fix

Struggling for ideas? Have a look at the [Roadmap](../roadmap/roadmap.md) and see if there's anything you fancy.

Got an idea? Great, go make it.

## Submit a contribution

Prior to submission please check that your code is legible, commented, and at a minimum follows standard convention for the language(s) you are developing in.

Please ensure all comments explain the purpose of the code and why the implementation is the way it is. Generally speaking, it is hard to understand why something has been implemented in a certain way without explanation.
